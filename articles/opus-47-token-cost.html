Bolt

速報です！ Opus 4.7の価格は据え置き——でも請求額は増えています。「え？」と思った方、正しい反応です。今回はPrismと一緒に、トークナイザ変更の裏側を掘り下げます。

Prism

「料金表が変わらない＝コストが変わらない」——この等式が成り立たなくなった瞬間を解剖します。特に日本語ユーザーにとっては他人事ではありません。

まず3行で要点を押さえよう。

  • 2026年4月16日にリリースされた Claude Opus 4.7 は、公式価格が据え置き（入力 $5 / 出力 $25 per MTok）
  • しかし新しいトークナイザの採用により、同じテキストが 1.0〜1.35 倍のトークン数にカウントされるようになった
  • 料金表は変わっていないのに、実質的な請求額は最大35%増。特に日本語・コード・構造化データで顕著で、英語圏より日本のチームの方がダメージがデカい

何が起きたのか

Opus 4.7 は性能改善の一環として、テキストをモデルが扱える単位に分割する「トークナイザ」を刷新した。Anthropic の公式マイグレーションガイドによれば、新トークナイザは従来モデルと比べて同じテキストを 1 倍〜1.35 倍のトークン数として処理するという（コンテンツにより最大約 35% 増）。

文字単価は動いていない。変わったのは「1 つのテキストが何トークンにカウントされるか」という前提そのもの。つまり値段表の数字は不動なのに、請求書の合計額は勝手に膨らむ構造になっている。

コンテンツタイプ別の増加率イメージ

コンテンツタイプ おおよその増加率
英語のプレーンテキスト ほぼ 1.0 倍（影響軽微）
コード・構造化データ（JSON等） 1.3 倍前後
日本語・非英語テキスト 1.35 倍に近い、もしくは超える

ここが日本人開発者にとっての最大のポイントだ。非英語はもともと英語よりトークン効率が悪いうえに、今回の変更は「コードと非英語」に偏って効いてくる。英語圏のユーザーより、日本語メインで使っているチームの方が確実にインパクトが大きい。

Bolt

英語圏のメディアは「1.0〜1.35倍」を一般論として扱っていますが、日本語ユーザーはレンジの上限側に張り付くのがポイント。他人事じゃありません。

独立検証では「1.47倍」の報告も

公式は「1.0〜1.35 倍」と幅を持たせているが、リリース直後に実測データを公開した開発者によれば、技術ドキュメントで約 1.47 倍、Claude Code で使う CLAUDE.md ファイルで約 1.45 倍 という、公式レンジの上限を超える数字が出ている。

これが示しているのは、実運用のコンテンツ（コード＋自然言語＋構造化データが混ざったもの）では、公式レンジの上限〜それ以上に張り付くという現実だ。Claude Code ユーザーのほとんどがこの領域にいる。

つまり「1.0〜1.35 倍」のレンジのうち、多くの人は下限ではなく上限側を引くと思っておいた方が安全、ということになる。

Prism

公式レンジの「1.0〜1.35倍」という表現自体が、英語プレーンテキストを下限、非英語+コードを上限として設計されたレンジです。つまり日本の開発者は構造的に上限側を引く。これは偶然ではなく、トークナイザの性質上の必然です。

追い打ち①：Claude Code のデフォルトが xhigh に

Opus 4.7 では推論の深さを制御する effort level に、新しく xhigh というティアが追加された。high と max の中間に位置するものだ。

そしてClaude Code では、全プランでこの xhigh がデフォルトになっている。

xhigh はモデルがより深く考え、より長く出力する。結果として出力トークン数も自然に増える。

つまり構造としては：

  • 入力：新トークナイザで最大 1.35 倍（さらに実測では 1.45〜1.47 倍）
  • 出力：xhigh デフォルトでさらに増加

この掛け算が、「同じようなタスクを投げているのに、Pro / Max プランのクォータがやたら早く尽きる」という体感を生んでいる。

救いはある。low-effort の Opus 4.7 が、medium-effort の Opus 4.6 とほぼ同等の性能を出すという報告があるからだ。つまり effort を 1 段下げるだけで、品質を保ったままトークン消費を抑えられるケースは多い。

Bolt

「low の 4.7 ≒ medium の 4.6」。この換算レートを覚えておくと、effort 調整のときの判断がグッと楽になります。まずは /config で確認してみて！

追い打ち②：プロンプトキャッシュの無効化

Anthropic のプロンプトキャッシュはモデル単位で分かれている。Opus 4.6 から 4.7 に切り替えた瞬間、既存のキャッシュプレフィックスはすべて無効化される。

切り替え後の流れはこうなる：

  1. 最初のセッションはコールドスタート（全キャッシュミス）
  2. 新しく書き込まれるプレフィックスは 1.3〜1.45 倍サイズに膨らんでいる
  3. 以降のキャッシュリードも、その膨らんだサイズに対して課金される

キャッシュ割引（約 90% off）は引き続き効くが、ベースが 1.45 倍に膨らんだものに 90% 割引を掛けるので、割引後の絶対額も当然上がる。仕組みとしては壊れていないが、払う総額は増えている。

Prism

ここは多くの記事がまだ触れていない盲点です。「切り替えた瞬間キャッシュが吹き飛び、コールドスタートで膨らんだサイズを払う」——二重苦の構造になっています。移行のタイミングも戦略的に考える必要があります。

実務への影響リスト

  1. 予算管理の破綻：月次 AI 予算を 4.6 時代の消費量ベースで組んでいたチームは、何もしなくても 20〜35% オーバーする可能性
  2. レート制限に早く到達：トークン数ベースのレート制限が、これまでより早く発動する
  3. max_tokens 不足事故：4.6 時代の max_tokens 設定が相対的に小さくなり、出力が途中で切れる事故が増える
  4. 観測性グラフの段差：歴史的なトークン消費のダッシュボードに、モデル切り替え日でステップチェンジが発生する。過去データとの素直な比較ができなくなる
  5. count_tokens API の戻り値が変わる：クライアント側で文字数からトークン数を推定しているロジックは全面的に書き直しが必要

今すぐやるべき対策 5 つ

1. max_tokens に 3〜5 割のヘッドルームを追加

Anthropic の公式ガイドも「max_tokens を更新して十分なヘッドルームを持たせること」と明記している。コンパクション（要約）のトリガー値も同時に見直す。

2. Claude Code の effort level を下げる

デフォルトの xhigh は、多くの日常タスクにはオーバースペック。high や medium で通るタスクが大半なので、体感しながら段階的に下げるのがおすすめ。low-effort の 4.7 ≒ medium-effort の 4.6 という目安を覚えておくと判断しやすい。

3. 本番切り替え前に必ず並行検証

Anthropic 自身が「非本番環境で先にテストし、プロンプト調整の要否と実コスト変化を把握してから移行せよ」と推奨している。少なくとも主要なワークロードについては、4.6 と 4.7 で同じ入力を流してトークン数と実コストをログ比較する期間を設けるべき。

4. task_budget（ベータ）を活用

Opus 4.7 で追加された、1 回の実行あたりのトークン上限を固定する機能。暴走コストを防ぐ最後の砦になる。特にエージェント系のワークロードでは設定推奨。

5. モデル ID のハードコードを洗い出す

claude-opus-4-6 を直書きしているコードは自動では上がらない。grep で全リポジトリを検索してから、計画的に切り替えるべき。ただし切り替えた瞬間、上記のコスト増が効くことを忘れずに。CI の予算アラートも同時にチューニングしておきたい。

Bolt

「とりあえず最新版に上げておこう」で痛い目に遭うパターンです。5つ全部やらなくても、まずeffort level を下げるとmax_tokens に余裕を持たせるの2つだけでもやっておくと安心。

それでも 4.7 に上げる価値はあるのか

コストだけを見ると厳しい値上げに見えるが、Opus 4.7 には明確な改善もある：

  • 視覚入力の解像度向上：2576px / 3.75MP まで対応（従来の約 2〜3 倍）
  • /ultrareview コマンド：シニアレビュアー級のコードレビューを実行（設計上の欠陥やロジックの穴を指摘）
  • 1M トークンコンテキストが標準価格で利用可能（long-context プレミアムなし）
  • .docx / .pptx 編集などナレッジワーカー系タスクで顕著な性能向上
  • エージェント実行の信頼性向上（長時間タスク・マルチステップ推論）

これらを使いこなすユースケースなら、トークン増の元は十分に取れる。

逆に、これらの改善を活かさないまま惰性で切り替えると、純粋な値上げとしてしか跳ね返ってこない。

Prism

「上げるべきか、留まるべきか」は、結局「4.7の新機能を活かすワークロードがあるか」に帰着します。惰性での切り替えは純粋な値上げ。目的ある切り替えは投資。同じ行動でも意味がまったく変わります。

まとめ

Opus 4.7 のトークナイザ変更は、悪意ではなく技術的な副作用だとしても、「価格は上げないが、みんなが気づかないところで使用量が勝手に増える」という実質ステルス値上げに近い構造になっている。

特に日本語を主戦場にしているチームは、英語圏のユーザーより影響が大きく出る可能性が高い。切り替えるなら最低限、

  • effort level を見直す
  • max_tokens に余裕を持たせる
  • 並行検証期間を設ける

の 3 点は絶対にやっておきたい。「料金表が変わらない＝コストが変わらない」とはもう言えない時代だということを、まず前提として共有するところから始めるのがいいだろう。
