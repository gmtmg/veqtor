こんにちは、Compassです。今回のテーマは「Hooks」。Claude Codeに「ルールをプログラムする」仕組みです。CLAUDE.mdの指示は「お願い」でしたが、Hooksは「強制」できます。危険な操作を確実に止めたり、保存のたびに自動フォーマットしたり。一緒にステップバイステップで学んでいきましょう。

Hooksとは何か ― CLAUDE.mdとの決定的な違い

Hooksとは、Claude Codeの特定のタイミングで自動的に実行されるシェルスクリプトのことです。

たとえるなら、こういうイメージです。

  • CLAUDE.md = 「ここに書いてあるルールを守ってね」というお願い
  • Hooks = 「このルールに違反したら自動的にブロックする」という法律

CLAUDE.mdは便利ですが、あくまでLLMへの指示です。Claudeが「うっかり」無視してしまう可能性がゼロではありません。一方、Hooksはシェルスクリプトとして実行されるので、100%確実に動作します。

具体例で見てみましょう。

# CLAUDE.mdに書いた場合
「rm -rf は絶対に使わないでください」
→ Claudeが「わかりました」と言いつつ、
  文脈によっては実行してしまうリスクがある

# Hooksで設定した場合
PreToolUseフックで rm -rf を検出 → exit 2
→ コマンド実行前に100%ブロックされる

つまり、Hooksは「信頼するけど検証する」を実現する仕組みです。CLAUDE.mdで方針を伝え、Hooksで確実にガードする。この組み合わせが最も安全です。

設定ファイルと基本構造

Hooksの設定は、JSON形式の設定ファイルに記述します。設定ファイルは3つの場所に置けます。

設定ファイルの配置場所

# 1. ユーザー全体（すべてのプロジェクトに適用）
~/.claude/settings.json

# 2. プロジェクト用（Gitでチームと共有可能）
.claude/settings.json

# 3. プロジェクト用・ローカル（.gitignoreされる）
.claude/settings.local.json

迷ったら.claude/settings.jsonがおすすめです。プロジェクトごとに設定でき、チームメンバーとも共有できます。

基本のJSON構造

Hooksの設定は、以下のような構造になっています。

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "/path/to/your-script.sh",
            "timeout": 10000
          }
        ]
      }
    ]
  }
}

構造を分解してみましょう。

  • hooks: Hooks設定のルートキー
  • PreToolUse: イベント名（後で詳しく解説します）
  • matcher: どのツールに対して発火するか（例: Bash、Edit、Write）
  • hooks（内側）: 実行するフックの配列
  • type: 常に "command"
  • command: 実行するシェルコマンドまたはスクリプトのパス
  • timeout: タイムアウト（ミリ秒）。省略時はデフォルト値が使われます
Compass

JSONの構造、思ったよりシンプルですよね。「イベント名」「マッチするツール」「実行するコマンド」の3つを指定するだけ。この基本パターンを覚えれば、あとはコピペで応用できます。安心して進みましょう。

3大イベントを理解する ― PreToolUse / PostToolUse / Stop

Hooksが発火するタイミングは、大きく3つあります。それぞれの特徴を見ていきましょう。

PreToolUse ― ツール実行「前」

PreToolUseは、Claudeがツールを実行する直前に発火します。最大の特徴はブロック機能です。

  • スクリプトがexit 2を返すと、そのツール実行が中止されます
  • matcherにはツール名を指定します（Bash、Edit、Write など）
  • stdinにはツール名と入力パラメータがJSON形式で渡されます

主な用途は、危険なコマンドのブロック、特定ファイルの保護、操作ログの記録です。

PostToolUse ― ツール実行「後」

PostToolUseは、ツールが正常に完了した直後に発火します。

  • ツールの実行をブロックすることはできません（すでに完了しているため）
  • matcherにはツール名を指定します
  • stdinにはツール名と実行結果がJSON形式で渡されます

主な用途は、自動フォーマット、自動テスト実行、ログ記録です。

Stop ― 応答完了時

Stopは、Claudeが応答をすべて終えたタイミングで発火します。

  • スクリプトがexit 2を返すと、Claudeが会話を続行します
  • matcherは不要です（ツール単位ではないため）
  • 完了通知や品質チェックに最適です

比較表

イベント 発火タイミング ブロック matcher 主な用途
PreToolUse ツール実行前 exit 2 で中止 ツール名 コマンド防止、ファイル保護
PostToolUse ツール実行後 不可 ツール名 自動フォーマット、ログ
Stop 応答完了時 exit 2 で続行 不要 通知、品質チェック

この3つを組み合わせることで、Claude Codeの振る舞いをきめ細かく制御できます。

実践：5つのHooksレシピ

ここからは実際に動くHooksを5つ紹介します。すべてそのまま使えるコードです。

レシピ1: 危険コマンドをブロックする

rm -rf や git push --force をmainブランチに実行しようとしたとき、確実にブロックします。

settings.json の設定:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/block-dangerous.sh",
            "timeout": 5000
          }
        ]
      }
    ]
  }
}

.claude/hooks/block-dangerous.sh:

#!/bin/bash
# stdinからJSON入力を読み取る
INPUT=$(cat)

# tool_inputからcommandフィールドを抽出
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

# commandが空なら何もしない
if [ -z "$COMMAND" ]; then
  exit 0
fi

# rm -rf をチェック
if echo "$COMMAND" | grep -qE 'rm\s+-rf\s+/'; then
  echo '{"decision":"block","reason":"rm -rf / は禁止されています"}'
  exit 2
fi

# mainへのforce pushをチェック
if echo "$COMMAND" | grep -qE 'git\s+push\s+.*--force.*\s+main'; then
  echo '{"decision":"block","reason":"mainへのforce pushは禁止されています"}'
  exit 2
fi

# 問題なければ通過
exit 0

このスクリプトは、stdinから受け取ったJSONの中の command フィールドを検査します。危険なパターンに一致すると exit 2 を返してブロックし、理由をstdoutにJSON形式で出力します。

レシピ2: 編集後に自動フォーマット

ファイルが編集されるたびに、Prettierで自動フォーマットします。

settings.json の設定:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/auto-format.sh",
            "timeout": 15000
          }
        ]
      }
    ]
  }
}

.claude/hooks/auto-format.sh:

#!/bin/bash
# stdinからJSON入力を読み取る
INPUT=$(cat)

# 編集されたファイルパスを取得
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

# ファイルパスが空なら何もしない
if [ -z "$FILE_PATH" ]; then
  exit 0
fi

# 対象の拡張子かチェック
case "$FILE_PATH" in
  *.js|*.ts|*.jsx|*.tsx|*.json|*.css|*.html)
    # Prettierが使える場合のみ実行
    if command -v npx &> /dev/null; then
      npx prettier --write "$FILE_PATH" 2>/dev/null
    fi
    ;;
esac

exit 0

PostToolUseなので、ファイルの書き込みが完了した後にフォーマッターが走ります。Claudeの出力を上書きする形で整形されるため、常にきれいなコードが保たれます。

レシピ3: 完了時にデスクトップ通知

Claudeがタスクを終えたら、macOSの通知で教えてくれます。長い作業を任せて別の仕事をしているときに便利です。

settings.json の設定:

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/notify-done.sh",
            "timeout": 5000
          }
        ]
      }
    ]
  }
}

.claude/hooks/notify-done.sh:

#!/bin/bash
# stdinからJSON入力を読み取る
INPUT=$(cat)

# 最後のメッセージを取得（通知に表示する）
STOP_REASON=$(echo "$INPUT" | jq -r '.stop_reason // "完了"')

# macOSの通知を送信
osascript -e "display notification \"Claude Codeが作業を完了しました\" with title \"Claude Code\" subtitle \"理由: ${STOP_REASON}\" sound name \"Glass\""

exit 0

Stopイベントなので、matcherは不要です。Claudeが応答を返し終わるたびに通知が届きます。

Compass

この通知フック、筆者のお気に入りです。長いリファクタリングを任せてコーヒーを淹れに行っても、「ポン」と音が鳴って完了を教えてくれます。Linuxの方は notify-send に置き換えてくださいね。

レシピ4: 特定ファイルの編集を禁止する

.env ファイルや認証情報をClaude Codeが触れないようにします。

settings.json の設定:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/protect-files.sh",
            "timeout": 5000
          }
        ]
      }
    ]
  }
}

.claude/hooks/protect-files.sh:

#!/bin/bash
# stdinからJSON入力を読み取る
INPUT=$(cat)

# 編集対象のファイルパスを取得
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

if [ -z "$FILE_PATH" ]; then
  exit 0
fi

# 保護対象のパターンをチェック
BASENAME=$(basename "$FILE_PATH")
case "$BASENAME" in
  .env|.env.*|credentials.json|*.pem|*.key)
    echo "{\"decision\":\"block\",\"reason\":\"${BASENAME} は保護対象ファイルです。手動で編集してください。\"}"
    exit 2
    ;;
esac

# ディレクトリベースの保護
case "$FILE_PATH" in
  */secrets/*|*/.ssh/*)
    echo '{"decision":"block","reason":"このディレクトリは保護されています"}'
    exit 2
    ;;
esac

exit 0

.env、credentials.json、秘密鍵ファイルなど、機密性の高いファイルへのアクセスを遮断します。ファイル名だけでなくディレクトリパスでも判定できます。

レシピ5: Bashコマンドの監査ログ

Claudeが実行するすべてのBashコマンドをログファイルに記録します。

settings.json の設定:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/audit-log.sh",
            "timeout": 5000
          }
        ]
      }
    ]
  }
}

.claude/hooks/audit-log.sh:

#!/bin/bash
# stdinからJSON入力を読み取る
INPUT=$(cat)

# コマンドを抽出
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

if [ -z "$COMMAND" ]; then
  exit 0
fi

# ログディレクトリを作成
LOG_DIR="${CLAUDE_PROJECT_DIR:-.}/.claude/logs"
mkdir -p "$LOG_DIR"

# タイムスタンプ付きでログに記録
LOG_FILE="$LOG_DIR/audit-$(date +%Y-%m-%d).log"
echo "[$(date '+%Y-%m-%d %H:%M:%S')] $COMMAND" >> "$LOG_FILE"

# ブロックはしないので exit 0
exit 0

PreToolUseを使っていますが、exit 0 で通過させるため、ブロックはしません。純粋なログ記録です。日付ごとにファイルが分かれるので、あとから「Claudeが何をしたか」を振り返れます。

なお、複数のレシピを組み合わせる場合は、同じイベント名のhooks配列に追加してください。

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "bash .claude/hooks/block-dangerous.sh" },
          { "type": "command", "command": "bash .claude/hooks/audit-log.sh" }
        ]
      },
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "bash .claude/hooks/protect-files.sh" }
        ]
      }
    ]
  }
}

環境変数とstdin/stdout通信プロトコル

フックスクリプトは、Claude Codeから情報を受け取り、結果を返す「通信プロトコル」を持っています。ここを理解すると、自由自在にスクリプトが書けるようになります。

利用可能な環境変数

フックスクリプトの中では、以下の環境変数が使えます。

環境変数 内容
CLAUDE_PROJECT_DIR プロジェクトのルートディレクトリ
CLAUDE_SESSION_ID 現在のセッションID
CLAUDE_CONVERSATION_ID 現在の会話ID

特に CLAUDE_PROJECT_DIR はよく使います。ログの保存先やスクリプトのパス解決に便利です。

stdinに渡されるJSON（PreToolUse）

PreToolUseフックには、以下のようなJSONがstdinに渡されます。

{
  "hook_type": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "git push --force origin main",
    "timeout": 120000
  }
}

ツールによって tool_input の中身が変わります。

  • Bash: command（実行するコマンド文字列）
  • Edit: file_path、old_string、new_string
  • Write: file_path、content

終了コードの意味

終了コード PreToolUseでの意味 Stopでの意味
0 ツール実行を許可 通常終了
2 ツール実行をブロック 会話を続行させる
その他 警告を表示して続行 警告を表示して終了

stdoutの出力形式

フックスクリプトのstdoutに出力したJSONは、Claudeにフィードバックされます。

# ブロック時の出力例
{
  "decision": "block",
  "reason": "この操作は禁止されています"
}

# 通過時にメッセージを渡す例
{
  "hookSpecificOutput": "フォーマット完了: 3ファイルを整形しました"
}

reason はClaudeに伝わるので、なぜブロックされたかをClaudeが理解して、別のアプローチを試みてくれます。

応用テクニック ― async・matcher・デバッグ

非同期フック（async）

通知やログ記録など、結果を待つ必要がないフックは非同期で実行できます。

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/send-slack.sh",
            "timeout": 10000,
            "async": true
          }
        ]
      }
    ]
  }
}

"async": true を指定すると、Claude Codeはスクリプトの完了を待たずに次の処理に進みます。Slack通知や外部APIへの送信など、時間のかかる処理に適しています。

matcherの正規表現パターン

matcherには正規表現が使えます。

# 複数ツールにマッチ（パイプ区切り）
"matcher": "Edit|Write"

# すべてのツールにマッチ（省略も可）
"matcher": ".*"

# MCPサーバーのツールにマッチ
"matcher": "mcp__myserver__search"

MCPツールの場合、命名規則は mcp__サーバー名__ツール名 です。たとえば、myserver というMCPサーバーの search ツールなら mcp__myserver__search になります。

デバッグ方法

フックがうまく動かないときは、以下の方法で調べましょう。

  1. /hooks コマンド: Claude Codeの中で /hooks と打つと、現在登録されているフックの一覧と状態を確認できます
  2. stderrへのログ出力: スクリプト内で echo "debug: $VARIABLE" >&2 とすれば、stderrにデバッグ情報を出力できます。stderrはClaudeのフィードバックに影響しません
  3. ログファイルへの書き出し: 複雑なデバッグには、一時ファイルに入力JSONを保存すると便利です
#!/bin/bash
# デバッグ用: 入力JSONをファイルに保存
INPUT=$(cat)
echo "$INPUT" > /tmp/hook-debug-input.json
echo "入力を /tmp/hook-debug-input.json に保存しました" >&2

# 通常の処理を続行
echo "$INPUT" | jq -r '.tool_input.command // empty'
exit 0

デバッグが済んだら、ログ出力の行は削除しておきましょう。

まとめ

この記事のポイントを整理します。

  1. Hooks = 確実なガードレール。CLAUDE.mdの「お願い」と違い、シェルスクリプトで100%実行されます
  2. 3つのイベント: PreToolUse（実行前・ブロック可）、PostToolUse（実行後・整形向き）、Stop（完了時・通知向き）
  3. 設定はJSON。.claude/settings.json に書くだけで有効化されます
  4. 通信はstdin/stdout。JSONを受け取り、終了コードとJSONで結果を返します
  5. exit 2 がカギ。PreToolUseでは「ブロック」、Stopでは「会話続行」を意味します
  6. 組み合わせが強力。危険コマンド防止 + 自動フォーマット + 通知 を同時に設定できます

CLAUDE.mdで方針を伝え、Hooksで確実にガードする。この二段構えで、Claude Codeをより安全に、より便利に使いこなしてください。
