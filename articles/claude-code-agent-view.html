Claude Codeの使い方が根本から変わる

これまでClaude Codeは「1つのターミナルで1つの会話」が基本でした。バグ修正中にPRレビューを頼みたくなったら、別のターミナルを開いて別のセッションを立ち上げる必要がありました。

2026年5月のWeek 20アップデート（v2.1.139〜v2.1.142）で、この制約が大きく変わりました。

  • Agent View — 複数のClaude Codeセッションを1画面で管理するダッシュボード
  • /goal — 完了条件を設定してClaudeを自律的に複数ターン稼働させるコマンド
  • Fast Mode on Opus 4.7 — 高速モードがOpus 4.7で動作するように

この3つを組み合わせると、「バグ修正、PRレビュー、テスト修正を3つ同時にディスパッチし、必要なときだけ介入する」というワークフローが実現します。

Agent View ― 全セッション一元管理ダッシュボード

起動方法

claude agents

ターミナル全体にダッシュボードが表示され、すべてのバックグラウンドセッションが状態別にグループ化されます。

Pinned
  ✽ clawd walk cycle          Write assets/sprites/clawd-walk.png           3m

Ready for review
  ∙ jump physics              github.com/example/game/pull/2048          ●  2h

Needs input
  ✻ power-up design           needs input: double jump or wall climb?       1m

Working
  ✽ collision detection       Edit src/physics/CollisionSystem.ts           2m

Completed
  ✻ title screen              result: menu, options, and credits done       9m
  ∙ sound effects             result: 14 SFX exported to assets/audio       4h

セッションの状態アイコン

状態 表示 意味
Working アニメーション付き ツール実行中・レスポンス生成中
Needs input 黄色 あなたの入力や許可を待っている
Idle 暗め 次の指示を待機中
Completed 緑 タスク正常完了
Failed 赤 エラーで終了
Stopped グレー 手動で停止された

基本操作

キー 操作
↑ / ↓ セッション行の選択
Space Peek（プレビューパネルを開く）
Enter / → セッションにアタッチ（フル会話に入る）
← デタッチ（ダッシュボードに戻る）
Ctrl+T セッションをピン留め
Ctrl+R セッション名の変更
Ctrl+X 停止（2秒以内に再度押すと削除）
Esc Agent Viewを閉じる

セッションのディスパッチ（タスク投入）

Agent Viewの下部にある入力欄にプロンプトを入力してEnterを押すと、新しいバックグラウンドセッションが起動します。各プロンプトは独立したセッションとして実行されます。

3つのディスパッチ方法

1. Agent Viewから

入力欄にタスク内容を書いてEnter。複数のプロンプトを連続で入力すれば、並列でセッションが走ります。

investigate the flaky SettingsChangeDetector test
address review comments on PR 1234
refactor auth module to use JWT

カスタムサブエージェントを使う場合は先頭に名前を書くか、@で指定します。

@code-reviewer address review comments on PR 1234

2. 既存セッションから

現在のセッション内で/bgを実行すると、バックグラウンドに移行します。

/bg run the test suite and fix any failures

または空のプロンプトで←を押すと、セッションがバックグラウンド化されAgent Viewが開きます。

3. シェルから直接

# バックグラウンドセッションを直接起動
claude --bg "investigate the flaky test"

# サブエージェントを指定して起動
claude --agent code-reviewer --bg "address review comments on PR 1234"

# 名前を付けて起動
claude --bg --name "flaky-test-fix" "investigate the flaky test"

Peekとアタッチ ― 効率的な介入

Agent Viewの設計思想は「必要なときだけ介入する」です。2段階のインタラクションモデルで実現されています。

Peek（軽量プレビュー）

Spaceを押すと、セッションの最新出力やClaudeからの質問が表示されます。ここで直接返答することもでき、多くの場合はPeekだけで十分です。フル会話を開く必要がありません。

  • 選択肢の質問には数字キーで回答可能
  • Tabで提案された返答を補完
  • !をプレフィックスに付けるとBashコマンドとして送信

アタッチ（フル会話）

Enterで完全な会話画面に入ります。通常のClaude Codeセッションとまったく同じで、すべてのコマンドとショートカットが使えます。

空のプロンプトで←を押すとデタッチしてAgent Viewに戻ります。デタッチしてもセッションは止まりません。バックグラウンドで作業を続けます。

worktreeによるファイル編集の分離

複数のセッションが同じファイルを同時に編集したら壊れるのでは？ この問題をClaude Codeはgit worktreeで解決しています。

バックグラウンドセッションがファイルを編集する前に、Claude Codeは自動的に.claude/worktrees/配下に独立したworktreeを作成します。各セッションは同じリポジトリを参照できますが、書き込みは完全に分離されます。

  • すでにworktree内で起動された場合はスキップ
  • gitリポジトリでない場合もスキップ（並列編集に注意）
  • セッション削除時にClaude作成のworktreeも削除される（未コミットの変更は失われる）

worktree分離を無効にしたい場合は以下を設定します。

// .claude/settings.json
{
  "worktree": {
    "bgIsolation": "none"
  }
}

Supervisorプロセス ― ターミナルを閉じても動き続ける

バックグラウンドセッションはsupervisorプロセスによってホストされます。ターミナルやAgent Viewとは独立したプロセスです。

  • Agent View初回起動時に自動起動、全セッション完了後に自動終了
  • ターミナルを閉じてもセッションは継続
  • スリープ後も復帰（シャットダウンでは停止）
  • Claude Codeのアップデート後も自動的に新バイナリで再起動
  • 完了後約1時間のアイドルでプロセスを解放、再アタッチ時に自動復元

/goal ― 完了条件で自律稼働させる

通常のClaude Codeは1ターンごとに制御が戻ります。/goalは「この条件が満たされるまで自分で続けて」と指示するコマンドです。

/goal all tests in test/auth pass and the lint step is clean

設定した瞬間にClaudeが動き始め、各ターン終了後に高速な評価モデル（Haikuクラス）が条件達成をチェックします。「まだ」なら次のターンが自動的に始まり、「達成」ならゴールがクリアされます。

向いているタスク

  • モジュールのAPI移行 — すべての呼び出し元がコンパイル通るまで
  • 設計書の実装 — すべての受入基準が満たされるまで
  • 大きなファイルの分割 — 各ファイルがサイズ上限以下になるまで
  • issueの消化 — ラベル付きキューが空になるまで

効果的な条件の書き方

  • 計測可能な終了状態を書く: 「テストが通る」「ビルドが成功する」「git statusがクリーン」
  • 検証方法を明記する: 「npm testが終了コード0で完了」
  • 制約を入れる: 「他のテストファイルは変更しない」
  • ターン上限を入れる: 「または20ターンで終了」

他の自律実行手段との比較

手段 次のターンの条件 停止条件
/goal 前のターンが終了 モデルが条件達成を確認
/loop 設定した時間間隔 手動停止 or Claudeの判断
Stop hook 前のターンが終了 カスタムスクリプト / プロンプト

/goalとAuto Modeは補完関係にあります。Auto Modeはツール呼び出しごとの許可プロンプトを省略し、/goalはターンごとの制御を省略します。組み合わせると、完了条件が達成されるまで完全に自律的に動作します。

操作コマンド

# ゴール設定（即座にClaudeが動き始める）
/goal all tests in test/auth pass and the lint step is clean

# 状態確認（ターン数・トークン消費量など）
/goal

# ゴール解除
/goal clear

非対話モードでも使えます。

claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"

Fast Mode on Opus 4.7

/fastで切り替えられる高速モードが、Opus 4.6からOpus 4.7に更新されました。

  • 同じモデル品質で約2.5倍の速度
  • 料金は$30/$150 per MTok（Opus 4.6 Fast Modeと同じ）
  • 高速なイテレーションやライブデバッグに最適
/fast

Opus 4.6にピン留めしたい場合は環境変数を設定します。

CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE=1

実践ワークフロー：3タスク同時実行

Agent View + /goal + Auto Modeの組み合わせで、以下のような並列開発が可能になります。

ステップ1: Agent Viewを開く

claude agents --permission-mode auto

ステップ2: 3つのタスクをディスパッチ

# 入力欄に順番に入力してEnter
/goal fix the flaky auth test until npm test exits 0
refactor UserService to use the new API
@code-reviewer review PR #1234

ステップ3: 作業中は他のことをする

Agent Viewで進捗を確認しつつ、別のターミナルで自分の作業を続けます。「Needs input」の行が出たらSpaceでPeekして回答するか、Enterでアタッチします。

ステップ4: 結果を確認

PRが作成されていればステータスドットが表示されます。緑（チェック通過）ならマージするだけです。

シェルからのセッション管理

Agent Viewを開かなくても、シェルからバックグラウンドセッションを管理できます。

コマンド 用途
claude agents Agent Viewを開く
claude agents --cwd <path> 特定ディレクトリのセッションのみ表示
claude attach <id> セッションにアタッチ
claude logs <id> 直近の出力を表示
claude stop <id> セッションを停止
claude respawn <id> セッションを再起動（会話は継続）
claude rm <id> セッションをリストから削除
claude daemon status supervisorの状態を確認

注意点とリミテーション

  • レート制限は共有: 10セッション並列なら、1セッションの約10倍のペースでクォータを消費
  • セッションはローカル実行: スリープでは保持されるが、シャットダウンで停止
  • worktree削除に注意: Agent Viewでセッションを削除するとworktreeも消える（未コミットの変更を含む）
  • Agent Viewはリサーチプレビュー: v2.1.139以降が必要。UIやショートカットは今後変更の可能性あり
  • /goalの条件は最大4,000文字: 評価モデルは会話履歴から判断するため、Claudeが出力した結果に基づく条件を書く

まとめ

  1. Agent Viewはclaude agentsで起動。複数セッションの状態を1画面で確認し、Peek/アタッチで必要なときだけ介入する
  2. ディスパッチは3通り: Agent View入力欄、/bg、claude --bg
  3. worktree分離で並列セッションのファイル編集が安全に独立
  4. /goalで完了条件を設定すると、評価モデルが各ターン後にチェックし達成まで自律稼働
  5. Auto Mode + /goalの組み合わせで完全自律動作が可能
  6. Fast ModeがOpus 4.7に更新。同品質で2.5倍速
  7. supervisorプロセスがターミナル不要でセッションを管理。閉じても動き続ける
